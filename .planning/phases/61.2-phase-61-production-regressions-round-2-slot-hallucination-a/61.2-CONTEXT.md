## Implementation Decisions

### Fix Candidate Selection

- **D-01 (Fix shape):** Ship **Fix 1 + Fix 2** from `61.2-INCIDENT.md`. Fix 1 = restore tool-invocation pressure scoped to post-info-gathering. Fix 2 = new anti-hallucination slot-time rule. Belt + suspenders, with Phase 61.1 anti-deadlock memory as the guard rail.

- **D-02 (Tool-invocation trigger condition):** The post-info-gathering trigger fires when **all four** preconditions are met: street, postal code, day preference, urgency. Once these are gathered, the prompt directs the agent to invoke `check_slot` (or `check_day` / `next_available_days` per existing rules). Prompt phrasing must stay non-directive (per `feedback_livekit_prompt_philosophy.md`) — frame as "once you have X, you have what you need to invoke Y," NOT as a hard rule.

- **D-03 (Anti-hallucination slot rule placement):** New dedicated **SLOT TIMES — CRITICAL RULE** section in `prompt.py`, parallel in shape to the Phase 61.1 `_build_address_validation_section`. Builder function naming follows the existing convention (`_build_slot_times_section(locale)`). EN + ES locale parity required. Same Phase 61.1 lesson applies: scope explicitly to the moment, NO silence escape hatch, do not include "silence is acceptable."

- **D-04 (Existing OUTCOME WORDS rule):** The existing `_build_outcome_words_section` (`prompt.py:260+`) ALREADY prohibits fabricated slot times. It did not fire in this incident — the planner must determine why before deciding whether to also amend it. See D-08 below for the research deliverable that locks this question.

- **D-05 (Full transcript pull):** Researcher MUST pull the full Supabase transcript for incident call `AJ_W7woUYGhG5CV` from the `calls` table. The `goodbye_race.transcript_tail` only shows the last 3 turns — full transcript needed to determine whether the caller mentioned any slot info, or whether the agent hallucinated entirely from no input. - **D-07 (Cross-section interaction trace):** Per `feedback_deep_verify_before_fix.md` — researcher MUST trace every section of `prompt.py` AND every tool description in `livekit-agent/src/tools/` for state preconditions on tool invocation. Specifically check whether the Phase 61.1 reframe's new substring "gather the address normally" or "the pre-tool readback" creates a soft chicken-and-egg with `check_slot` invocation. Output: a written interaction matrix in RESEARCH.md.

- **D-08 (OUTCOME WORDS shadowing analysis — required research deliverable):** RESEARCH.md must answer: "Why did the existing OUTCOME WORDS rule fail to prevent the slot fabrication in incident `AJ_W7woUYGhG5CV`?" Hypothesis space: section-ordering shadows it, prompt is too long for the model to apply, ambiguity with TOOL NARRATION section, conflict with another rule, or pure model error. The answer determines whether Fix 2 is sufficient or whether OUTCOME WORDS also needs amending.

- **D-09 (Reproducibility UAT call):** A pre-fix LiveKit SIP UAT call MUST be placed (via the existing test SIP path used in Phase 61 onboarding test-call flow). Goal: determine whether zero-tool-invocation is universal or caller-specific. This is also the validation gate per D-11. Place against a staging/test environment if available; otherwise on production with the test tenant.

### Validation / Pre-Ship Gates

- **D-10 (Prompt invariant tests):** Lock new SLOT TIMES section + tool-invocation trigger phrasing in `tests/test_prompt_*.py`. Pattern follows Phase 61.1's `test_both_locales_pre_tool_readback_explicit` — must-be-present substrings + must-be-absent substrings, both EN and ES. NECESSARY but explicitly NOT sufficient (Phase 61.1 had 14 GREEN invariant tests and still deadlocked production).

- **D-11 (Behavioral E2E test):** Add a new test that simulates a LiveKit AgentSession with mocked Gemini RealtimeModel. Feed scripted user turns matching the incident shape ("yes/I need a plumber/this address/this postcode/Thursday/it's leaking"). Assert that `check_slot` (or `check_day` / `next_available_days`) is invoked once trigger preconditions D-02 are met. Catches "rule exists but model ignores it." Higher cost to write — researcher must scope this against existing test patterns and confirm feasibility.

- **D-12 (Live UAT call before ship — MANDATORY GATE):** A live LiveKit SIP test call MUST land successfully before Phase 61.2 is declared verified. "Successfully" = (a) tools are invoked when info is gathered, (b) no slot hallucination, (c) full booking flow completes OR a clean lead-capture happens. This is the explicit Phase 61.1 lesson: prompt-test invariants did not catch the deadlock; only a real call would have. NO ship without this gate.

- **D-13 (Staged rollout — DROPPED):** No feature-flag infrastructure exists in the LiveKit Python agent for per-tenant prompt gating. Building it for one prompt change is scope creep. Skipped. The D-12 UAT gate is the substitute risk control.

### Established Patterns
- **EN+ES locale parity (Phase 60.3 D-B-03 mandate):** Every prompt section that affects spoken output has EN and ES branches. Tool names are NOT translated. Reserved words / verdict tokens are NOT translated. The new SLOT TIMES section MUST have both branches.

- **No-feature-flag prompt:** `prompt.py` has no per-tenant or per-flag conditional inclusion of sections. All tenants get the same prompt. D-13 (staged rollout dropped) is consistent with this.
