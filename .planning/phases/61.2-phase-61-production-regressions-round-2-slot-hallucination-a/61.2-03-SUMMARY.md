## Pattern alignment

The new listener defined-and-cleaned-up shape mirrors the pre-existing `_on_state_change` listener:
- Defined inside `mute_input_during_tool` after closure state (`saw_fresh_speaking`, `unmute_event`) is set up
- Subscribed via `session.on(...)` in the body
- Unsubscribed via the same `try/except` block in `_unmute_logic`'s cleanup, covering both pyee API surfaces (`off` and `remove_listener`)
- Defensive `try/except Exception: pass` inside the callback body so a malformed event payload never breaks the lifecycle

The closure share (`saw_fresh_speaking[0]` mutated by both listeners) follows the existing list-as-mutable-cell idiom documented in the function's existing comment block.
