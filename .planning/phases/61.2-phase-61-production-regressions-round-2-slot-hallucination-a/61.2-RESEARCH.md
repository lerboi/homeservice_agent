## D-08 OUTCOME WORDS Shadowing Analysis

### Hypothesis space + likelihoods

| # | Hypothesis | Likelihood | Evidence (verified against `prompt.py`) |
|---|-----------|------------|----------------------------------------|
| (a) | **Section-ordering shadows it** — OUTCOME WORDS sits at index 4, but BOOKING (§14) re-contextualizes it. By the time the model is in info-gathering / scheduling mode, OUTCOME WORDS has been re-anchored as a *booking-confirmation* rule, not a *don't-propose-times* rule. | **HIGH (40%)** | OUTCOME WORDS opens *"the caller hangs up believing they have a confirmed appointment when nothing is in the system"* — framed around the **booking outcome**. | (b) | **Prompt is too long for the model to apply** — 1300+ lines of prompt; attention drops at distance. | **MEDIUM (25%)** | Plausible for any long prompt under realtime audio constraints. ### Required columns from `calls` (verified) [VERIFIED]

- `call_id`, `tenant_id`, `from_number`, `created_at`, `duration_seconds`
- `booking_outcome` (`booked` / `attempted` / `declined` / `not_attempted`)
- `disconnection_reason`
- `transcript_text`, `transcript_structured`
- `detected_language`

### Heuristic: tool-invocation rate

There is no `tool_call_log` column on `calls` [VERIFIED]. To approximate tool-invocation rate from the transcript alone:

- **Booked outcomes** (`booking_outcome = 'booked'`) imply `book_appointment` returned success → tool was invoked. HIGH confidence.
- **Attempted / declined** (`booking_outcome IN ('attempted', 'declined')`) imply tools were invoked at some point. MEDIUM confidence.
- **`not_attempted`** is the failure-mode bucket for both 61.1 (silence-deadlock) and 61.2 (zero invocations). The aggregator must surface these, separate them by symptom (silence-deadlock vs zero-invocation-with-conversation), and flag for manual triage.

### Heuristic: slot-hallucination signal

In `transcript_structured` (jsonb turn-by-turn), a slot-hallucination is a turn where:

- Role = `assistant`
- Content matches a regex like `\b(at|on|for)\s+\d{1,2}\s*(am|pm|AM|PM)\b` OR `\b(Monday|Tuesday|Wednesday|Thursday|Friday|Saturday|Sunday)\s+at\s+\d`
- AND the immediately preceding `user` turn does NOT contain that same time (caller-said-it check)
- AND `booking_outcome != 'booked'` (not legitimately said as part of a confirmed booking)

This is a coarse heuristic — false positives possible. Surface for human triage, don't auto-classify.

### Concrete query draft

```sql
-- .planning/queries/phase-61-call-aggregator.sql
-- Phase 61.x production-call aggregator. Run after a regression to find
-- comparable calls. Filter by date range to scope to "post-Phase-61 ship."

-- Q1: Outcome breakdown for post-Phase-61 calls
-- (Phase 61 shipped 2026-05-03 per 61.1-INCIDENT.md frontmatter)
SELECT
  date_trunc('day', created_at) AS day,
  booking_outcome,
  count(*) AS n_calls,
  avg(duration_seconds)::int AS avg_dur_s,
  count(*) FILTER (WHERE disconnection_reason = 'CLIENT_INITIATED') AS caller_hangups
FROM calls
WHERE created_at >= '2026-05-03'
  AND tenant_id = '24141cd0-5735-4c7a-82d5-994c6b821861'  -- "make it ai" — adjust as needed
GROUP BY 1, 2
ORDER BY 1 DESC, 2;

-- Q2: not_attempted calls — the regression bucket
SELECT
  call_id,
  created_at,
  duration_seconds,
  disconnection_reason,
  detected_language,
  -- First 500 chars of transcript for quick triage:
  left(transcript_text, 500) AS transcript_preview
FROM calls
WHERE created_at >= '2026-05-03'
  AND booking_outcome = 'not_attempted'
  AND duration_seconds >= 30  -- skip short hang-ups
ORDER BY created_at DESC
LIMIT 50;

-- Q3: Slot-hallucination heuristic — assistant turns with specific times
-- not preceded by a caller turn naming the same time. Coarse; for triage.
WITH assistant_time_turns AS (
  SELECT
    c.call_id,
    c.created_at,
    c.booking_outcome,
    (turn->>'content') AS content,
    turn_idx,
    LAG(turn->>'content') OVER (PARTITION BY c.call_id ORDER BY turn_idx) AS prev_content,
    LAG(turn->>'role') OVER (PARTITION BY c.call_id ORDER BY turn_idx) AS prev_role
  FROM calls c,
       jsonb_array_elements(c.transcript_structured) WITH ORDINALITY AS t(turn, turn_idx)
  WHERE c.created_at >= '2026-05-03'
    AND turn->>'role' = 'assistant'
    AND (turn->>'content') ~ '\b(at|on|for)\s+\d{1,2}\s*(am|pm|AM|PM)\b'
)
SELECT
  call_id,
  created_at,
  booking_outcome,
  content AS suspect_assistant_turn,
  prev_content AS preceding_caller_turn
FROM assistant_time_turns
WHERE booking_outcome != 'booked'
  AND (prev_content IS NULL OR prev_content !~ '\b\d{1,2}\s*(am|pm|AM|PM)\b')
ORDER BY created_at DESC
LIMIT 50;
```

- The tenant_id is hardcoded to "make it ai" because that's the only tenant in the two known incidents. Future runs can drop or parameterize the filter.

## Common Pitfalls

### Pitfall 1: Re-introducing the Phase 61.1 silence-deadlock
**What goes wrong:** Adding a new CRITICAL RULE that includes "silence is acceptable" or licenses non-response.
**Root cause:** Pattern-matching the address-validation rule too literally (the address rule USED to have it; was removed in 61.1).
**Avoidance:** D-10 invariant tests assert `"Silence is acceptable" not in section`. Same lesson, codified.

### Pitfall 2: Translating tool names
**What goes wrong:** Spanish branch translates `check_slot` to `verificar_horario` etc.
**Root cause:** Forgetting that tool names are code identifiers wired to `src/tools/` registry.
**Avoidance:** D-10 invariant test asserts `"check_slot" in section` for both EN and ES. Pattern is established by Phase 61.1 verdict-token convention.

### Pitfall 3: Bloating OUTCOME WORDS or TOOL NARRATION instead of creating a new section
**What goes wrong:** Trying to fix the gap by amending two existing sections.
**Root cause:** False economy — "we already have OUTCOME WORDS, just patch it."
**Avoidance:** D-08 verdict locks SLOT TIMES as a NEW dedicated section, mirroring the address-validation pattern. Cross-reference only; no body merge.

### Pitfall 4: Hard-imperative phrasing in Fix 1
**What goes wrong:** Writing "you MUST invoke check_slot" or "you are REQUIRED to invoke now."
**Root cause:** Overcorrecting from Phase 61.1's softer reframe.
**Avoidance:** Fix 1 phrased as "you have what you need to invoke" (outcome-oriented per `feedback_livekit_prompt_philosophy.md`). D-10 invariant test asserts `"you must invoke" not in section`.

### Pitfall 5: Shipping without D-12 live UAT
**What goes wrong:** All `pytest` tests pass; ship; another regression surfaces.
**Root cause:** Phase 61.1's lesson: 14 GREEN tests, still deadlocked production.
**Avoidance:** D-12 is non-negotiable per CONTEXT. The verifier in `/gsd-verify-work` MUST require evidence of a placed UAT call before declaring the phase verified.
