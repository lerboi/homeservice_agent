## Phase 61.2 — Gemini-Server Cancellation Cascade Mitigation (2026-05-06)

**Failure mode discovered (D-09, call AJ_vV4DM5AG9t7W):** Gemini 3.1 Flash Live performs server-side VAD on the input audio stream and cancels in-flight generation + discards pending function calls when caller speech is detected — including very brief utterances ("Hello.") that fall below `silence_duration_ms=2500`. The result is fragmented agent speech: turns split mid-sentence, with continuation turns starting with leading spaces. Pre-fix UAT recorded 5 cancellations in 230s; the call hung up `not_attempted`.

**The original Phase 61.2 hypothesis (zero tool invocations + slot fabrication) did NOT reproduce.** Tools fire. The actual failure is structural in the LiveKit/Gemini stack, not in the prompt.

**Fix A — Mute pattern extension** (`livekit-agent/src/tools/{check_caller_history,check_customer_account,capture_lead}.py`):
The `mute_input_during_tool` helper (`_availability_lib.py`) was previously called only by the four availability/booking tools. Phase 61.2 extends it to the three data-fetch tools that run BLOCKING Supabase I/O. `transfer_call` and `end_call` remain intentionally untouched (they end the session).

**Fix B — Robust unmute lifecycle** (`livekit-agent/src/tools/_availability_lib.py`):
Two changes to `mute_input_during_tool`:
1. `_TOOL_MUTE_FALLBACK_S` raised from 15.0s to 25.0s. The booking-section name+address readback runs 10-14s; on a server-cancelled call the recovery generation may extend further. 15s left no margin.
2. New listener on `function_tools_executed` that resets `saw_fresh_speaking[0]` on each fresh tool execution during the mute window — re-anchors the unmute on the recovery generation's clean speak/listen cycle rather than on a stale earlier one.

**Fix C — Server-cancellation telemetry** (`livekit-agent/src/agent.py`):
New `_ServerCancelHandler` (mirrors `_GoodbyeDiagHandler` shape) installed on `livekit.plugins.google.realtime` and `livekit.plugins.google` loggers. Watches for two warnings and increments counters on `_diag_record`:
- `server cancelled tool calls` → `server_tool_cancellations`
- `received server content but no active generation` → `orphaned_server_content`

Counters flow into the `[goodbye_race]` log line + Sentry breadcrumb at call close. Pure observability — no behavior change.

**SDK 1.5.7 note (cross-link to Phase 63.2):** `livekit-agents==1.5.7` ships `fix: realtime reply generation after interruption` (one-line `return` in `agent_activity._realtime_reply_task:2811`) — addresses a downstream client-side symptom, NOT the upstream Gemini-server cancel-and-discard behavior. PR #5535/#5594 add a pausable-output mechanism but require opt-in via `RoomOutputOptions` and `can_pause`-capable output (deferred from 61.2 scope; see future spike).

**Test invariants:** `livekit-agent/tests/test_tool_mute_invariants.py` (5 substring-grep tests; pattern follows `tests/test_no_generate_reply_in_src.py`):
- `test_data_fetch_tools_mute` — every data-fetch tool calls `mute_input_during_tool`.
- `test_terminal_tools_do_not_mute` — terminal tools do NOT.
- `test_unmute_fallback_at_least_25s` — guards the fallback floor.
- `test_function_tools_executed_listener` — guards the re-anchor subscription.
- `test_server_cancel_handler_installed` — guards Fix C handler installation + the two diag fields.

**D-12 post-fix UAT (call `{POST_FIX_CALL_ID}`):** server_tool_cancellations = `{POST_FIX_CANCELS}` (baseline 5). Verdict: merge.

**Lesson:** Prompt edits cannot prevent server-side VAD cancellations on Gemini 3.1 Flash Live. The structural mute pattern is the only known mitigation today. Telemetry now exists (Fix C) so future regressions in this area land with quantitative evidence rather than transcript-tail snapshots.

**Merge SHA:** `{MERGE_SHA}` (livekit-agent main).
