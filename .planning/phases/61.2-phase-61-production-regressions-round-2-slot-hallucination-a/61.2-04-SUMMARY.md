## Decisions Made

- **Mirror existing `_GoodbyeDiagHandler` shape exactly.** Same `__init__(self, diag_record)` constructor, same try/except no-raise contract, same per-call install + finally-block cleanup pattern. Lowers cognitive overhead and matches the planning doc's explicit mandate (CONTEXT D-C-01: "Mirror the existing `_GoodbyeDiagHandler` … new class … installed on `logging.getLogger('livekit.plugins.google.realtime')` AND `logging.getLogger('livekit.plugins.google')`").
- **Attach to BOTH `livekit.plugins.google.realtime` and `livekit.plugins.google`.** First is where the warnings are emitted today per RESEARCH § Assumptions; second is defensive — if a future SDK bump moves emission up the namespace, the parent handler still catches.
- **Counter pattern uses lazy default-zero `dict.get(key, 0) + 1`.** Means the [goodbye_race] log line omits the field entirely on calls where the cascade never fired — keeps healthy-call records tidy and turns the field's mere presence into a "cascade happened on this call" signal.
- **Did NOT add per-emit `logger.info` traces.** The upstream plugin already logs each warning at WARNING level; adding our own duplicate trace would just be noise. The goal is per-call aggregate counters on the goodbye record, not per-warning logs.
