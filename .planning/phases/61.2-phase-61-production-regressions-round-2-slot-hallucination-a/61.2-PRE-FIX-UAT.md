## Implications for Plan 02 / Plan 04

The original Plan 02 (three prompt-line edits in `livekit-agent/src/prompt.py`) targets the wrong layer. Prompt edits cannot prevent server-side VAD cancellations. The phase needs to be re-scoped around structural fixes:

1. Extend `mute_input_during_tool` from the 4 availability/booking tools to the 4 always-on data-fetch tools (`check_caller_history`, `check_customer_account`, `capture_lead`; leave `transfer_call`/`end_call` alone — they end the session intentionally).
2. Make the mute unmute logic robust against multi-step generation. Either raise the 15s fallback or refine the listener so it tracks the *new* generation step's speak→listen cycle rather than any speak→listen cycle (`_availability_lib.py:96-114`).
3. Add a logging filter on `livekit.plugins.google.realtime` that surfaces `"server cancelled tool calls"` warnings to a counter on `diag_record` — gives post-call telemetry visibility into the cascade.
4. (Optional, hygiene) Investigate the 1.5.7 pausable-output mechanism (PR #5535/#5594). Probably won't fully solve the cascade because it depends on `can_pause`-capable output, but it's the only 1.5.7-specific lever.
