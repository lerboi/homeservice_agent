## Lessons

1. **Patch-bump hygiene phases work — when the audit is honest about what doesn't apply.** Phase 63.2 shipped in ~1h end-to-end (scaffold + preflight + checkpoint wait + merge + skill + summary). The 2026-05-05 Explore-agent audit explicitly predicted zero forced `src/` edits (both 1.5.7 fixes target call-site patterns this stack doesn't use). Prediction held — `git diff --name-only origin/main..HEAD` = `pyproject.toml`. The pattern is reusable for 1.5.8 / 1.5.9 / future patches that audit clean. **If a future audit cannot honestly predict zero forced edits, the phase grows scope or splits — the patch-bump shape is reserved for clean audits only.**

2. **Pytest baseline drift requires a verification protocol, not a fail-fast posture.** When the actual count diverged from the plan-authored expectation (`254/1` vs `284/9 + 2`), the executor's correct response was a venv rollback to the prior pin and re-run of the same test files. Identical failures = pre-existing baseline issue, NOT a 1.5.7 regression. **Treat "different pytest count from plan" as a signal to verify, not a stop signal.** The codebase advances faster than plans can be re-authored; the rollback re-run is the correct disambiguation tool.

3. **Cut-from SHA drift between plan-authoring and execute is expected on long-cycle phases.** `61a2e6e` (plan-authored 2026-05-05) → `187d207` (execute 2026-05-05) was a ~9-commit drift. The correct response: cut from the actual main tip, verify all D-04 preserved SHAs are still in lineage, document the drift in HUMAN-UAT. **Don't try to force the cut-from to match the plan's stale citation** — that's a fictional reproduction, not the real upgrade path.

4. **Evidence-capture gaps at human-verify checkpoints are a real failure mode.** The user issued `merge` based on direct dashboard + on-call observation, but didn't backfill raw artifacts (Railway URL, Twilio call ID, log tail, observational warning counts) into HUMAN-UAT. **The verdict is still trustworthy** (the user observed the phenomena directly), but the audit trail is weaker. **Future patch-bump phases should enforce a "no merge verdict without backfilled HUMAN-UAT" gate** if this pattern recurs across multiple phases. For 63.2 alone, the SUMMARY explicitly documents the gap so future readers understand the evidence boundary.

5. **The hygiene-bump muscle-memory is the actual deliverable.** This phase did not change observable production behavior. The cutoff race and the tool-call cancellation warnings still fire. The agent's prompt, tools, and call flow are byte-identical to the post-Phase-64-revert state. **What shipped is the proof that we can execute a patch-bump cycle in ~1h with confidence — Railway gate, UAT gate, `--no-ff` merge, all 12 preserved SHAs intact.** This is the muscle that will cash in on the next material upgrade (1.5.8 / 1.6) when the SegmentSynchronizer cutoff race fix actually lands.
