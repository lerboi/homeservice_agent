**GREEN commit (sibling `11d7a24`):**

`src/prompt.py::_build_address_validation_section` reframed in both locales:

EN body now opens:
> "ADDRESS VALIDATION — CRITICAL RULE:
> After book_appointment or capture_lead returns, this rule governs how you speak back what the tool found. Before calling the tool, gather the address normally and read back what the caller said to confirm you heard it correctly — that is the pre-tool readback, and it is not 'validated' phrasing."

ES body mirrors:
> "VALIDACIÓN DE DIRECCIÓN — REGLA CRÍTICA:
> Después de que book_appointment o capture_lead retorne, esta regla rige cómo repite lo que la herramienta encontró. Antes de llamar a la herramienta, recopile la dirección normalmente y repita lo que el llamante dijo para confirmar que la oyó correctamente — esa es la repetición previa a la herramienta, y no es un lenguaje de 'validado'."

The verdict-driven branching (validated / validated_with_corrections / unvalidated) and the 6-phrase prohibition list are PRESERVED VERBATIM in both locales. The only structural changes:

1. Each post-tool gating clause now opens with `"After a tool return that contains ..."` (EN) / `"Después de un retorno que contenga ..."` (ES) — making the post-tool scope explicit at every branch.
2. The prohibition is now phrased `"After a tool return, NEVER use any of these phrases unless that return contained ..."` (EN) / `"Después de un retorno, NUNCA use ninguna de estas frases a menos que ese retorno contenga ..."` (ES).
3. Closing prose: EN `"Saying any of these after a tool return without the verdict to back them up is a serious failure ... Before the tool runs, the ordinary readback rules apply and this prohibition does not."` ES mirror `"... Antes de que corra la herramienta, las reglas ordinarias de repetición se aplican y esta prohibición no."`

Docstring updated to document the Phase 61.1 fix.
