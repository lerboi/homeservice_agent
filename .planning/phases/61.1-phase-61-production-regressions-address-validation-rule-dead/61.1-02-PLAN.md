<objective>
Fix the two `google_maps.py` defects from `61-REVIEW.md` (WR-01 + WR-02) folded into Phase 61.1 because they are likely to surface as new regressions if left:

**WR-01:** When `tenant_id` is falsy, the telemetry insert into `gmaps_validate_events` violates the NOT NULL `tenant_id` constraint. The bare `except Exception:` at lines 535-543 silently swallows this, defeating D-C2' observability for the very calls (early/anonymous) where it matters most. Fix: skip the insert with a single warn log when `tenant_id` is falsy.

**WR-02:** Empty `address_lines` (`[]`) reach Google's API, which returns HTTP 400 with `INVALID_ARGUMENT`. `_is_unsupported_region_400` matches the substring `invalid_argument` and misclassifies as `verdict=unsupported_region`. Two consequences: (a) call records `cost_micro_cents=1700` (false billing rollup; Google does NOT bill for malformed-input 400s); (b) on-call observability loses signal — empty-address calls show as a region-coverage problem rather than upstream-capture problem. Fix: short-circuit empty `address_lines` to `verdict=error` BEFORE the HTTP call (per WR-02 suggested fix in 61-REVIEW.md lines 113-118).
