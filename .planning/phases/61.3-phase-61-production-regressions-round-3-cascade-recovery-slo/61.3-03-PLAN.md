```python
async def _attempt_tool_result_replay(
    deps: dict,
    session,
    mute_set_at_ms: int,
) -> None:
    diag = deps.get("_diag_record")
    last_frame_ms = diag[0].get("last_audio_frame_at") if diag else None
    stall_confirmed = (last_frame_ms is None or last_frame_ms <= mute_set_at_ms)
    if not stall_confirmed:
        return
    state_str = deps.get("_last_tool_state")
    call_id = deps.get("_last_tool_call_id")
    tool_name = deps.get("_last_tool_name")
    if not (state_str and call_id and tool_name):
        return
    if diag:
        diag[0]["stalled_generation_recoveries"] = (
            diag[0].get("stalled_generation_recoveries", 0) + 1
        )
    try:
        rt_session = None
        if session._activity is not None:
            rt_session = session._activity.realtime_llm_session
        if rt_session is None:
            raise RuntimeError("no active rt_session for replay")
        from livekit.agents import llm as _llm
        synthetic_output = _llm.FunctionCallOutput(
            call_id=call_id,
            name=tool_name,
            output=state_str,
            is_error=False,
        )
        chat_ctx = rt_session.chat_ctx.copy()
        chat_ctx.items.append(synthetic_output)
        await rt_session.update_chat_ctx(chat_ctx)
        logger.info(
            "[tool_mute] stall-recovery replay sent id=%d tool=%s state=%.80s",
            deps.get("_tool_mute_id", 0), tool_name, state_str,
        )
    except Exception as e:
        logger.warning("[tool_mute] stall-recovery replay failed: %s", e)
        if diag:
            diag[0]["stalled_generation_replay_failed"] = (
                diag[0].get("stalled_generation_replay_failed", 0) + 1
            )
```

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Tampering | Replay sends stale tool data — `_last_tool_call_id` from a prior tool call mismatched with `_last_tool_state` from the current one | mitigate (best-effort) | The stall guard `last_frame_ms <= mute_set_at_ms` scopes the replay window to the CURRENT mute. If the call_id is mismatched, the Gemini server will ignore the FunctionResponse (call_id not recognized) and `stalled_generation_replay_failed` increments. Counter telemetry via `[goodbye_race]` JSON makes this observable. No call breakage. (Pitfall 2 in RESEARCH.md.) |
| T-03-02 | Race condition | Replay races user speech (D-06 ordering violation could let user VAD-cancel before replay lands) | mitigate | Source-order requirement enforced by `test_replay_before_set_audio_enabled`. The replay `await` completes (or fails) BEFORE `set_audio_enabled(True)` runs — VAD cannot fire on input that is still muted. |
| T-03-03 | Information disclosure | `_last_tool_state` may include caller-history names or context strings sent to Gemini | accept | Same data already sent to Gemini in the original tool execution; replay re-sends the same payload to the same recipient. No new disclosure surface. |
| T-03-04 | Denial of service | `update_chat_ctx` raises and propagates into `_unmute_logic`, blocking the unmute and trapping the caller | mitigate | The await is wrapped in `try/except Exception` (D-07). Any exception is caught, logged, counter-incremented, and control returns to `_unmute_logic` which proceeds to the listener-cleanup + unmute path. No path to a permanent mute. |
| T-03-05 | Spoofing | Synthetic `FunctionCallOutput` injected into chat_ctx with a `call_id` not actually issued by the model | accept | The call_id comes from `FunctionToolsExecutedEvent.function_calls[-1].call_id` (Plan 01) — that IS a model-issued id. Edge case: if a malicious actor controlled the SDK's event stream they could spoof, but that requires breaching the agent process. Out of scope. |

No new network surfaces. The single new outbound action (`update_chat_ctx`) uses the same Gemini-server channel the original tool already used.
