## Decisions Made

- **Helper at module scope, not nested.** The plan's `<action>` block specifies "module scope (NOT nested inside `mute_input_during_tool`)". Confirmed: the new function appears at indentation 0 immediately after the closing of `mute_input_during_tool`'s body. This makes the `^async def _attempt_tool_result_replay` substring grep work and keeps it inspectable without unwrapping closures.
- **Local SDK import inside the try block.** The plan specifies `from livekit.agents import llm as _llm` at the call site, not at module top. This avoids any circular-import risk with `..lib.slot_calculator` and keeps module load light. The import is inside `try`, so an SDK shape change at most shows up as a logged warning and replay-failed counter increment (D-07).
- **Replay fires before listener cleanup (NOT just before set_audio_enabled).** The plan specifies "BEFORE the listener cleanup AND BEFORE the unmute". Source order: `unmute_reason = …` → `await _attempt_tool_result_replay(...)` → listener cleanup `try/except` → `if deps.get("_tool_mute_id") == mute_id: session.input.set_audio_enabled(True)`. The test only asserts replay before `set_audio_enabled(True)`, but the plan's stronger ordering is also satisfied by construction.
- **Did not modify the success branch.** Recovery only fires on the timeout fallback path. If `unmute_event.wait()` returned cleanly (Gemini spoke + agent transitioned `speaking → listening`), no stall happened and no replay is appropriate. This matches D-04: stall = no audio frames advanced.
- **Did not modify the listener cleanup or the mute_id-guarded unmute block** — the plan explicitly forbade touching them.
