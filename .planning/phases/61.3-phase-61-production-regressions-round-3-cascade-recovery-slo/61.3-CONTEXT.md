## Phase Boundary

Recovery from Gemini-server VAD/TTS-stall cancellations on the LiveKit voice agent (Gemini 3.1 Flash Live). 61.2 owned cascade *prevention* via the structural mute pattern (Fix A/B/C); 61.3 owns cascade *recovery* — what happens after a Gemini server-side stall causes a tool-call response to be cancelled and the regenerated agent response loses its tool-result context.

**The specific failure 61.3 closes:** UAT Call `AJ_5NcSoiaZGZTJ` (2026-05-06) — `check_day` returned `STATE:day_has_slots count=9` for Thursday May 7; Gemini's post-tool TTS stalled for 22 seconds; mute fallback fired at 25s; user said "Hello" at unmute; VAD cancelled the stalled generation; regeneration lacked tool-result context; agent told caller "we don't have anything open tomorrow" — direct inversion of the tool result.

**Out of scope:** the four gaps from `61.2-VERIFICATION.md` are NOT the unit of work. The "listener miss" framing is incorrect (listener works); transcript fragmenting is a downstream symptom of the same cascade; greeting playout is orthogonal. 61.3 closes the slot-hallucination gap with a single mechanism, and the other quality items get re-evaluated *after* the recovery lands and a fresh D-12 UAT shows what residual symptoms remain.

<decisions>
## Implementation Decisions

### Scope

- **D-01:** Single-fix scope — stall-detection + tool-result replay. Do NOT bundle gap #2 (listener emitter "miss" — listener works correctly), gap #3 (transcript fragmenting — symptom of cascade, not separate fix), or gap #4 (greeting playout — orthogonal). Re-measure after this lands.
- **D-02:** D-12 mandatory live SIP UAT remains the ship gate. Same posture as 61.2. Cascade telemetry counters (`server_tool_cancellations`, `orphaned_server_content`, plus new `stalled_generation_recoveries` from this phase) are the objective measurement. Reuse `61.2-PRE-FIX-UAT.md` as the cascade baseline reference.

### Recovery mechanism

- **D-03:** Two-part recovery in async layer — (1) stall detection in `_availability_lib.mute_input_during_tool` post-fallback path, (2) tool-result replay via `update_chat_ctx`'s tool_results path. Recovery does NOT live in `_ServerCancelHandler` — that's a `logging.Handler`, synchronous, no async/session access (validated B4 impossibility).
- **D-04:** Stall detection trigger — when the 25s fallback fires (i.e., `function_tools_executed` listener gate succeeded but `unmute_event` was never set because Gemini never transitioned listening→speaking→listening), check `diag_record[0].get("last_audio_frame_at")` against the mute-set timestamp. If no audio frames advanced during the speaking window: stall confirmed.
- **D-05:** Replay path — construct a synthetic `FunctionCallOutput` containing the last tool's STATE string from `deps["_tool_call_log"]` (or equivalent), and send via `update_chat_ctx` on the underlying `RealtimeSession`. The `tool_results` send at `realtime_api.py:637-638` is unconditional — NOT gated on `mutable_chat_context`, so it works on `gemini-3.1-flash-live-preview` (validated against installed SDK 1.5.7).
- **D-06:** Replay timing — fire BEFORE re-enabling input (i.e., before `set_audio_enabled(True)`). VAD threshold is `silence_duration_ms=2500` (`agent.py:461`), giving ~2.5s grace after unmute, but the goal is to never let user speech race with the recovery. Replay first, then unmute.
- **D-07:** Replay is best-effort. If `update_chat_ctx` raises or the `RealtimeSession` is no longer live, log + increment a telemetry counter (`stalled_generation_replay_failed`) and proceed to unmute. Do not block the call on replay failure.

### Telemetry

- **D-08:** Extend Fix C's `_diag_record` with two new counters — `stalled_generation_recoveries` (replay attempts) and `stalled_generation_replay_failed` (replay errors). Mirror the conditional-emit pattern (`server_tool_cancellations` style — only present in `[goodbye_race]` JSON when count > 0).
- **D-09:** `last_audio_frame_at` is already populated by Fix C (`agent.py` `_GoodbyeDiagHandler` writes it). Reuse — do NOT add a parallel tracking mechanism.

### Tests

- **D-10:** Substring-grep invariant tests in the same shape as `tests/test_tool_mute_invariants.py` (Phase 61.2 pattern). Add tests asserting: (a) replay code path exists in `_availability_lib.py` and is reachable from the fallback branch; (b) replay uses `update_chat_ctx` (not `generate_reply` — that's gated and would silently no-op); (c) replay fires BEFORE `set_audio_enabled(True)`; (d) the two new diag counters are accumulated; (e) the conditional-emit pattern is preserved (no eager init of new counters).
- **D-11:** Behavioral test — DEFERRED. No mocking of `RealtimeSession.update_chat_ctx` in this phase. The D-12 live UAT is the behavioral gate. Pattern matches 61.2 D-11 deferral.

### Skill closeout

- **D-12:** Append Phase 61.3 subsection to `.claude/skills/voice-call-architecture/SKILL.md` documenting: (a) the stall-detection + replay mechanism, (b) the corrected understanding of the `mutable_chat_context` gate (tool_results bypass it), (c) the listener-miss-was-not-a-miss correction (close the false-trail finding from 61.2), (d) updated cascade-failure-mode memory pointer.

### Claude's Discretion

- Naming of the new diag counter keys (`stalled_generation_recoveries` is a placeholder — planner can rename if a better fits the existing counter style).
- Internal helper function names within `_availability_lib.py`.
- Test file location/naming as long as they sit alongside `test_tool_mute_invariants.py` and run in the same suite.

</decisions>
